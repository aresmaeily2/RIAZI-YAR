# پیکربندی AI، STT و TTS — ریاضی‌یار (MVP)

نسخه سند: ۱.۰.۰ | **وضعیت هر بخش با صداقت کامل ثبت شده است.**

## ۱) راهنمای مبتنی بر AI (آنلاین)

### وضعیت واقعی: «پیاده‌سازی‌شده سمت کلاینت + نیازمند سرور واسط؛ بدون کلید غیرفعال»

- **پیش‌فرض**: راهنمای **محلی قاعده‌محور** (`LocalGuideEngine`) فعال است. این
  هوش مصنوعی نیست و اپ هرگز چنین ادعایی نمی‌کند؛ در UI منبع پاسخ صادقانه
  («محلی» یا «آنلاین») نمایش داده می‌شود.
- **راهنمای آنلاین** (`HttpAiGuideClient`): آماده اتصال به یک **سرور واسط (proxy)**
  است. اپ هیچ کلید API در خود ندارد و نباید داشته باشد. آدرس سرور فقط در زمان
  ساخت تزریق می‌شود:

```bash
flutter build apk --release \
  --dart-define=RIAZIYAR_GUIDE_ENDPOINT=https://your-proxy.example.com/guide
```

- اگر پیکربندی نشود (پیش‌فرض): سوییچ «راهنمای آنلاین» در بخش والدین عملاً
  بی‌اثر است و همه پاسخ‌ها از راهنمای محلی می‌آید. **هیچ خطای شبکه‌ای رخ نمی‌دهد.**

### قرارداد سرور واسط (برای پیاده‌سازی آینده)

```
POST {RIAZIYAR_GUIDE_ENDPOINT}
Content-Type: application/json
{
  "utterance":  "متن گفتار کودک (≤۱۲۰ نویسه؛ ممکن است خالی باشد)",
  "prompt":     "متن پرسش فعلی",
  "hints":      ["راهنمای ۱", "…"],       // از محتوای درس
  "wrongStreak": 2,                        // تعداد اشتباه متوالی
  "activityType": "countAndChoose",
  "lessonId": "l1_a1"
}
پاسخ ۲۰۰: {"message": "پیام کوتاه فارسی کودک‌پسند", "action": "showHint"}
  action ∈ keepGoing | showHint | showAnswerStrategy | backToLesson | safeFallback
خطا: هر کد غیر ۲۰۰
```

الزامات سمت کلاینت (اعمال‌شده در کد): خروجی باید JSON ساختاریافته باشد؛ پیام
بیش از ۳۰۰ نویسه ⇒ رد؛ **سقف بایت ۸KB در حین خواندن جریانی** اعمال می‌شود
(انباشت کامل قبل از سقف انجام نمی‌شود — ممیزی ۱.۰.۱)؛ **فقط URI مطلق HTTPS
با host معتبر — اعتبارسنجی کامل قبل از هرگونه اتصال**؛ timeout ۸ ثانیه؛
گواهی نامعتبر رد می‌شود؛ در هر خطا، UI به راهنمای محلی برمی‌گردد با پیام امن
(`GuideMessages.offline` / `.invalidAiOutput`). پوشش تست: `test/ai_guide_http_test.dart`
و `test/guide_resolver_test.dart` (رفتار fallback از UI به هسته منتقل و تست شد).

### مسئولیت‌های امنیتی سرور واسط (خارج از دامنه MVP — مستند، نه پیاده‌شده)

- نگهداری کلید API مدل زبانی **فقط سمت سرور**.
- فیلتر محتوای نامناسب قبل از ارسال به مدل و پس از دریافت.
- محدودسازی نرخ درخواست (per-device)، لاگ بدون داده شناسایی‌پذیر کودک.
- گزینه‌های مدل: هر LLM تجاری (هزینه‌دار) یا مدل خودمیزبان (بدون هزینه API ولی
  هزینه سرور). هر دو با همین قرارداد سازگارند.

## ۲) تبدیل گفتار به متن (STT)

### وضعیت واقعی (ممیزی ۱.۰.۱): «به‌صورت امن غیرفعال شد»

**تحلیل مسیر داده (مبنای تصمیم):**

- در نسخه ۱.۰.۰ از پکیج `speech_to_text` (روی `SpeechRecognizer` اندروید)
  استفاده می‌شد. `SpeechRecognizer` یک سرویس سیستمی است و **نحوه پردازش
  صدا به موتور نصب‌شده روی دستگاه بستگی دارد**: روی بسیاری از دستگاه‌ها
  صدا برای پردازش به سرویس ابری سازنده (مثلاً گوگل) ارسال می‌شود و این
  رفتار از داخل اپ قابل تضمین یا راستی‌آزمایی نیست.
- چون پردازش آفلاین و سیاست داده قابل تأیید نبود، طبق بند ۱ ممیزی،
  قابلیت **به‌صورت امن غیرفعال شد** تا هیچ ادعای «کاملاً محلی» مطرح نباشد.

**اقدامات انجام‌شده (دفاع چندلایه):**

1. مجوز `RECORD_AUDIO` از `AndroidManifest.xml` حذف شد (اپ به میکروفون
   دسترسی ندارد).
2. پکیج `speech_to_text` از وابستگی‌ها حذف شد (هیچ کد/پلاگینی از این مسیر
   در APK نیست).
3. query سرویس `android.speech.RecognitionService` از Manifest حذف شد.
4. سرویس تزریق‌شده در اپ `DisabledSttService` است: همیشه «در دسترس نیست»
   با پیام کنترل‌شده.
5. دکمه‌های میکروفون با ثابت `kSpeechInputAvailable = false` از UI پنهان‌اند.
6. پیش‌فرض `speechInputEnabled` در تنظیمات به «خاموش» تغییر کرد.
7. صفحه والدین به‌جای سوییچ، **توضیح صادقانه** درباره چرایی غیرفعال‌بودن
   نشان می‌دهد.

**مسیر اصلی کودک دست‌نخورده است:** پاسخ‌دهی با دکمه‌های لمسی کامل،
کاملاً آفلاین و بدون تغییر رفتاری است.

### چک‌لیست فعال‌سازی دوباره (نسخه آینده — قبل از هرگونه وعده به والدین)

- [ ] انتخاب/تأیید موتور تشخیص گفتار **کاملاً آفلاین** (مثلاً recognizers
  آفلاین اندروید با `RecognizerIntent#EXTRA_PREFER_OFFLINE`) و آزمون واقعی
  اینکه با قطع اینترنت هم کار می‌کند.
- [ ] مستند سیاست داده: چه داده‌ای، کجا پردازش می‌شود، هیچ ارسال خارجی.
- [ ] آزمون میدانی دقت روی گفتار کودک ۶-۷ ساله فارسی‌زبان.
- [ ] رضایت آگاهانه والد: توضیح قابل فهم + پیش‌فرض خاموش + روشن‌کردن فقط
  با اقدام والد در بخش والدین.
- [ ] افزودن مجوز `RECORD_AUDIO` و پکیج `speech_to_text` (کد مرجع در
  تاریخ گیت نسخه ۱.۰.۰ موجود است).

## ۳) تبدیل متن به گفتار (TTS)

### وضعیت واقعی: «پیاده‌سازی با flutter_tts؛ وابسته به موتور TTS دستگاه»

- موتور: TTS سیستم‌عامل از طریق `flutter_tts`؛ زبان `fa-IR` در صورت وجود.
- اگر موتور دستگاه فارسی نداشته باشد: `status = unavailable` و خواندن بی‌صدا
  رد می‌شود (اپ کرش نمی‌کند؛ متن‌ها همچنان نمایش داده می‌شوند).
- کنترل کاربر: سوییچ «راهنمای صوتی» در تنظیمات والدین؛ سرعت ۰.۴ و زیر و بم ۱.۲
  (مناسب کودک).
- تست واحد با `StubTtsService` (لیست جمله‌های گفته‌شده را نگه می‌دارد).
- **صداقت مسیر داده (ممیزی ۱.۰.۱):** TTS فقط «خواندن متن» است و اپ صدایی
  ضبط نمی‌کند؛ اما موتور TTS خود دستگاه ممکن است بسته به تنظیمات کاربر
  برای دانلود/پردازش صدا از شبکه استفاده کند. این رفتار خارج از کنترل اپ
  است و ادعای «کاملاً آفلاین» نمی‌شود؛ والد می‌تواند آن را خاموش کند.
