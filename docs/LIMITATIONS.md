# محدودیت‌ها، ریسک‌ها و کارهای باز — ریاضی‌یار (MVP)

نسخه سند: ۱.۰.۰ | تاریخ: ۲۰۲۶-۱۰-۱۷

قاعده این سند: **فقط چیزهایی که واقعاً تأیید شده‌اند «انجام‌شده» نام می‌گیرند.**

## ۱) محدودیت‌های واقعی نسخه فعلی

1. **اجرای روی دستگاه/شبیه‌ساز انجام نشده است.** محیط ساخت نه شبیه‌ساز داشت و
   نه دستگاه. صحت‌سنجی از طریق ۵۴ تست واحد/ویجت و ساخت موفق APK انجام شد.
   اجرای میدانی پیش از هر استفاده واقعی با کودک الزامی است.
2. **صوت روی دستگاه آزمون نشده.** TTS/STT پیاده‌سازی واقعی دارند ولی «تست نشده
   روی دستگاه هدف» — به‌خصوص دقت STT برای صدای کودک نامعلوم است.
3. **همگام‌سازی ابری پیاده‌سازی نشده.** فقط قرارداد (`SyncContract`) + صف
   (`sync_queue`). هیچ داده‌ای از دستگاه خارج نمی‌شود.
4. **راهنمای آنلاین بدون سرور غیرفعال است.** سرور واسط (proxy) ساخته نشده؛
   قرارداد و کلاینت آماده است.
5. **محتوا نمونه است و توسط معلم بازبینی نشده** (`teacherReviewed: false`) —
   برچسب در UI نمایش داده می‌شود. بازبینی تخصصی پیش از انتشار واقعی الزامی است.
6. **پوشش آموزشی فقط یک واحد است**: شمارش اشیا (۱-۵، ۶-۹) + آزمون کوتاه.
7. **گیت والدین محافظت ساده است** (جمع دو رقمی) — ادعای امنیت بالا ندارد و در
   UI هم همین گفته شده.
8. **امضای APK با کلید debug است.** برای انتشار باید keystore تولید و
   `signingConfig` ریلیز تنظیم شود.
9. **APK دو معماری (arm, arm64) است**؛ x86_64 (شبیه‌ساز) در این محیط ساخته نشد
   (محدودیت دیسک) — روی ماشین معمولی با دستور استاندارد قابل ساخت است.
10. **ورود/نام کودک**: فقط نام مستعار غیرحساس؛ بدون ثبت‌نام و حساب کاربری.

## ۲) ریسک‌های شناخته‌شده

| ریسک | اثر | کاهش |
|---|---|---|
| دقت STT پایین برای صدای کودک | ورودی گفتاری بی‌فایده می‌شود | ورودی لمسی همیشه فعال و اصلی است؛ STT صرفاً افزودنی |
| نبود موتور TTS فارسی روی برخی دستگاه‌ها | خواندن دستور کار نمی‌کند | متن همه‌جا نمایش داده می‌شود؛ سوییچ صدا در تنظیمات |
| محتوای نمونه بدون بازبینی متخصص | خطای آموزشی احتمالی | برچسب صریح + بازبینی معلم پیش از انتشار |
| SQLite بدون رمزگذاری | دسترسی فیزیکی دستگاه به داده‌ها | داده‌ها فقط پیشرفت ریاضی و نام مستعار است؛ حساس نیست |
| تغییر وابسته‌ها در آینده (path_provider_android) | شکست بیلد | پین‌شده در pubspec با توضیح |

## ۳) کارهای باز (اولویت‌بندی‌شده)

**P0 — پیش از استفاده با کودک واقعی**
1. اجرای میدانی روی ۲-۳ دستگاه واقعی با چک‌لیست `TESTING.md` (بخش ۴).
2. بازبینی محتوای درس‌ها توسط معلم پایه اول و تیک `teacherReviewed`.
3. تولید keystore و امضای ریلیز.

**P1 — نسخه بعدی کوچک**
4. خودکار کردن فهرست درس‌های assets (حذف ثبت دستی).
5. تنظیم آستانه تسلط در UI والدین (مدل آماده است؛ UI ندارد).
6. نمایش تاریخچه تلاش‌ها در داشبورد والدین (داده در DB هست؛ UI تجمیعی دارد).
7. افزودن ۲-۳ فعالیت جدید در همان دو نوع موجود (محتوا فقط).

**P2 — افق بعدی**
8. پیاده‌سازی سرور واسط راهنمای آنلاین طبق قرارداد `AI_STT_TTS.md`.
9. همگام‌سازی ابری با پیاده‌سازی `SyncContract.flush`.
10. پشتیبانی از فایل صوتی ضبط‌شده پیش‌فرض (جایگزین TTS برای دستگاه‌های فقیر).
11. BLoC/Riverpod در صورت رشد وضعیت — فعلاً ChangeNotifier کافی است.

## ۴) بدهی فنی شناخته‌شده

- `childeName` پیش‌فرض «کاوشگر کوچک»؛ UI تغییر نام مستقل ندارد (فقط DB/مدل).
- بعضی پیام‌ها طول ثابت دارند؛ بین‌المللی‌سازی (l10n) انجام نشده — هدف فقط فارسی است.
- `web/` از قالب مانده ولی پشتیبانی وب هدف نیست.
- تست ویجت کامل برای همه ۸ صفحه وجود ندارد؛ جریان‌های منطقی پوشش داده شده‌اند.
